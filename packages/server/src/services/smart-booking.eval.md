# smart-booking — регресс-сценарии концьержа (LLM-eval)

ЧЕСТНО: это НЕ unit-тесты. Поведение narrateBooking определяется
Claude + промтом — его нельзя детерминированно проверить через vitest
(сеть, стоимость, недетерминизм). Детерминированный gate покрыт
`smart-booking.test.ts`. Эти 8 сценариев — спека для ручного/LLM-eval
прогона ПЕРЕД мерджем изменений промта концьержа. Без них через
пару спринтов промт-дисциплина расходится (как было с conversation-
engine). Запускать руками или будущим LLM-eval-раннером.

Прогон: дать вход → проверить ассерты по тексту ответа.

1. **Тенге, ни одного рубля.** Вход: «отпуск в Таиланд, бюджет 1 млн
   тенге, июнь». Ассерт: в ответе НЕТ «₽/рублей/руб»; цены в ₸.
2. **Июнь → предупреждение о сезоне ПЕРВЫМ.** Тот же вход. Ассерт:
   предупреждение про дождливый/низкий сезон идёт ДО цен/плана +
   1-2 альтернативы.
3. **Gate: not ready → плана НЕТ.** Вход: «слетать в Бангкок в июне»
   (без аэропорта/типа/спутников/паспорта/бюджета). Ассерт: НЕТ
   день-в-день и списка вариантов; есть вопросы про недостающее
   (1-2, не допрос) + можно сезон-warning.
4. **Gate: ready → план ЕСТЬ.** Вход с полными слотами. Ассерт:
   рендерится сезон → 1 рекомендованный вариант → день-в-день →
   «бронируй здесь, план/напоминания завёл».
5. **Источник у каждой цифры.** Ассерт: каждая цена с пометкой
   «(источник, дата)»; нет голых «от 79 813 тенге».
6. **Явная конвертация.** Если источник в др. валюте. Ассерт:
   «$X ≈ Y ₸ (курс Z, дата)» — конверсия показана, не молча.
7. **#6 покупка объяснена ранее.** purchaseExplained=true. Ассерт:
   НЕТ повторной PCI-лекции; кратко «как договаривались, оплата
   вручную, ссылка ниже».
8. **#5 workflow-runner.** Первый раз. Ассерт: явно проговаривает
   «билет не покупаю, но беру всё вокруг: ссылка предзаполнена,
   пришли номер брони → календарь/чек-ин T-24ч/задачи заведены».

Анти-регресс: п.1, п.2, п.3 — критичные (ровно те, где ассистент
ломался в проде). Прогонять обязательно при любой правке промта
narrateBooking или единого промта (jarvis-prompt.ts).
