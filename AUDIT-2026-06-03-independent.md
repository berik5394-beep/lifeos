## 🟠 HIGH (чинить до массовых юзеров; часть — риск отклонения)

5. **Нет age-gate / рейтинг не 17+** — нет даты рождения/проверки 16+ (EU). Токсичный режим предупреждается (`onboarding.tsx:194-205`), но не за возрастом. → собирать возраст + рейтинг 17+. (App Store §3/§8)

6. **Stale permission-строки на удалённую фичу** — `app.json:73-74`: камера/фото «для **счётчика калорий** / распознавания **еды**» — калории удалены. Apple отклоняет строки про несуществующие фичи. → переписать на сканирование расписаний/заметок. (App Store §4)

7. **Лишнее `WRITE_CONTACTS`** (`app.json:58`) — заявлено только чтение контактов, фичи записи нет. → убрать. (App Store §4)

8. **AUTH без поведенческих тестов** — НИ один тест не зовёт `auth.ts`/`bcrypt`/`signToken`/`refreshToken` (2 «совпадения» — ложные). Для платного приложения регистрация/логин/JWT/refresh-ротация **полностью непокрыты поведенчески** — регресс хэша или TTL уедет в прод зелёным. (Тесты §)

9. **Роуты/оркестратор — 0 поведенческого покрытия** — `*-capture.test.ts` и `jarvis-orchestrator-*.test.ts` это `readFileSync`+regex по исходнику (124 из 210 файлов — чистый grep). Хендлер, вернувший 500 / отдавший данные другого юзера (нет `userId`-скоупа) / записавший кривое — проходит все тесты. **Cross-user изоляция не проверена в рантайме.** (Тесты §)

10. **Гонка consume pending-action → двойная запись денег** (`services/pending-actions.ts:103-104`) — `takePendingAction` = peek + remove двумя запросами без транзакции. Два параллельных «да» (тап в app + «да» в Telegram, или дабл-тап) → `runConfirmedAction` дважды → **дубль расхода/дохода**. → атомарный `deleteMany` + действовать только при `count===1`. (Correctness §6)

11. **Нет `onDelete: Cascade` на ~18 core-моделях** (`schema.prisma`: Habit/Task/Expense/Income/JournalEntry/CalendarEvent/Pet/… строки 179,192,228,240,282,309,…) — `prisma.user.delete` упадёт по FK. Удаление аккаунта (требование Apple 5.1.1(v)) сейчас работает **через ручной упорядоченный каскад в роуте** (`auth.ts:340-428`), но это хрупко: добавил новую owned-модель и забыл в список → удаление падает для этого юзера. → добавить cascade в схему (additive-миграция) ИЛИ держать ручной список синхронным. (Correctness §7)

12. **Нет таймаута на memory-enrichment в горячем пути чата** (`jarvis-orchestrator.ts:999`, `v2-enrichment.ts:128`) — `fetchV2EnrichmentData` await-ится; каждый tier `.catch(()=>null)` (не бросит), но **нет таймаута**. Зависший pgvector-запрос блокирует ответ юзеру без верхней границы. → `Promise.race` с бюджетом ~800мс. (Correctness §4)
