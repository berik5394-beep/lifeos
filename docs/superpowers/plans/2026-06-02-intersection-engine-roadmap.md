# Движок пересечения — Roadmap + статус

**Обновлено:** 2026-06-02 (вечер)
**Что это:** живой план общего «движка пересечения» (north-star Berik) + лог сегодняшней работы. Подробная карта связей — `interconnection_map.md` (память).

---

## 1. Идея (одной строкой)

Один паттерн для ЛЮБОГО ресурса: **ёмкость ресурса vs сумма обязательств → если не хватает → защити главное → скажи «+Δ или опоздаешь / перенеси Y»**. Одно чистое ядро `computeCapacityFit`, тонкие адаптеры на каждый ресурс. Каждое действие любого инструмента влияет на цели/нагрузку других; мозг считает дефицит и говорит проактивно, вовремя, как Друг (сам прикидывает, не пристаёт, уточняет в момент конфликта).

## 2. Где мы СЕЙЧАС

Движок **доказан на 2 ресурсах, оба в проде:**
- 💰 **Деньги** — коуч по накоплениям (`savings-pace.ts computePortfolioPace`): главная фин-цель (квартира) + конкуренты + trade-off. Реактив после расхода + дневной брифинг. Флаг `FEATURE_V2_SAVINGS_COACH=all`.
- 🕐 **Время-в-день** — «день перегружен» (`capacity-fit.ts` + `day-load.ts`): Σ оценённого времени задач сегодня vs свободное время (окно − календарь − прошедшее). Реактив в `create_task`. Флаг `FEATURE_V2_DAY_LOAD=all`.

Ядро `computeCapacityFit` — ресурсо-агностичное (capacity vs Σdemand → fit/overflow по importance). Деньги пока на своём `computePortfolioPace` (свести на общее ядро — поздний рефактор).

## 3. Что сделано СЕГОДНЯ (2026-06-02) — всё в проде

1. **Коуч: мульти-цель фикс** — `pickCoachableGoal` берёт незакрытую цель, а не первую (баг «не бьётся»).
2. **Коуч: точность от даты цели** — `savedSoFar` считается с `YearlyGoal.createdAt`, не с 1 января (миграция).
3. **Коуч v2 portfolio** — все цели разом, якорь = самая денежная (квартира), trade-off «+Δ/мес или опоздаешь; велик отодвигает». Ревью APPROVED.
4. **Коуч-дедуп фикс** — реактив дедупится против СВОИХ инсайтов, не глушится дневным рефлектором.
5. **Честный ввод денег (#189)** — бот больше НЕ врёт про запись денег: надёжный детект суммы (даже «я потратил X»), детерминированное доспрашивание категории через FSM (multi-turn), запрет агенту заявлять о записи без вызова инструмента. Ревью APPROVED. (Прод-факт: «я потратил 100000»→«девушку»→«да» → реальная Expense-строка.)
6. **Движок пересечения, СРЕЗ 1 «День перегружен»** — общее ядро `computeCapacityFit` + время-адаптер + ИИ-оценка часов задачи (haiku, фоном) + реактив. Ревью APPROVED. Флаг `FEATURE_V2_DAY_LOAD=all`.

Сюита 2129 зелёная, tsc 0. Все 6 — задеплоены.

## 4. Дальше — ГОРИЗОНТЫ ВРЕМЕНИ (тот же паттерн, новые адаптеры на ТО ЖЕ ядро)

Berik: **день → неделя → месяц → год.**

- [x] **ДЕНЬ** — `day-load.ts` (готово, в проде).
- [x] **НЕДЕЛЯ** — `week-load.ts` (КОД ГОТОВ, ревью APPROVED, флаг `FEATURE_V2_WEEK_LOAD` ещё НЕ выставлен в Railway — ждём «пуш и деплой»). Ёмкость = `sumWeekCapacity` (Σ дневной ёмкости по ОСТАВШИМСЯ дням пн–вс, tz-aware); спрос = Σ `estimatedMinutes` незакрытых задач недели. Реактив в `create_task` ПОСЛЕ дня (день в приоритете — нет двойной строки). Дедуп ≤1/день vs source `week_load`. Коммиты ff17b2d/e4fc3d1/fe4428e/e2c4cf0.
- [x] **МЕСЯЦ — ПОЛНОСТЬЮ done (ревью APPROVED, флаг `FEATURE_V2_MONTH_LOAD=all` в проде).** Σ обязательств месяца (недельные цели + задачи) vs ёмкость оставшихся дней. Доставлен в 2 шага под одним флагом:
  - [x] **Data-слой:** `WeeklyGoal.estimatedMinutes Int?` + `estimate-goal-minutes.ts` (haiku, фоном, идемпотентно) + хуки REST `/goals/weekly` + планировщик `persistPlan`. Коммиты f54d14d/1ed417d/c34cbc6/a26348e/f3dd63e.
  - [x] **Нудж `month-load.ts`:** `localMonthStartUTC` (tz-хелпер) + `gatherMonthLoad` (demand задачи+цели, capacity `sumWeekCapacity` по оставшимся дням) + `describeMonthLoad`/`maybeMonthLoadLine` + каскад в `create_task` (day>week>month). Дедуп ≤1/день source `month_load`. Коммиты 21b0c1e/92822d6/904c52e. Спека `specs/2026-06-03-month-load-design.md`, план `plans/2026-06-03-month-load.md`.
- [x] **ГОД — done (ревью APPROVED-with-nits, фикс применён; флаг `FEATURE_V2_YEAR_LOAD`).** Framing = ПЕЙСИНГ измеримых не-денежных целей (Berik выбрал, не capacity-overload). Деньги-цели остаются у savings-coach. Доставлено целиком:
  - **Y1 захват прогресса:** инструмент `update_goal_progress` («прочитал 25 книг» → находит измеримую цель → пишет progress% с конвертацией `pctFromValue`). Закрыл блокер «progress никогда не обновлялся».
  - **Y2 пейсинг:** `goal-pace.ts` (`computeGoalPace` поверх прод-`computeSavingsPace`, `describeGoalPace`) — реактивно (строка в инструменте, source `goal_pace`) + проактивно (ветка дневного рефлектора, source `reflector`, гард свежести <0.5мес). Деньги/savings не тронуты.
  - Коммиты cad80f1/6d05038/2c62ba2/b26e12c/eec7ab2/8f6aabb. Спека `specs/2026-06-03-year-goal-pace-design.md`, план `plans/2026-06-03-year-goal-pace.md`.

**🏁 ДВИЖОК ПЕРЕСЕЧЕНИЯ ЗАВЕРШЁН: день ✅ → неделя ✅ → месяц ✅ → год ✅.** Все 4 горизонта + деньги — в коде. Деплой месяца+года ждёт «пуш и деплой».
