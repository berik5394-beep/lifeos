# Разбор цели при постановке — план (на согласование)

2026-11-08. Статус: **черновик, ждёт «да» Berik** (изменение мозга → план до кода).

## Зачем

Сейчас постановка годовой цели = просто запись: «Цель записана… Буду вести».
В момент постановки мозг НЕ смотрит ни на деньги, ни на время, ни на привычки.
Поперёк цель начинает жить только позже — детекторы в следующих тиках
(«траты съедают цель», «отстаёшь», «свободно в четверг»), разбивка — только
если попросить «разбей цель». Цель: **сразу при постановке** робот считает,
реально ли это, и предлагает первый шаг.

Пример ответа (цифры условные):

> Цель записана: «накопить 1 000 000 ₸ к декабрю».
> Это ~125 000 ₸ в месяц, а свободно у тебя сейчас ~40 000 ₸ (доходы минус траты за месяц) — не хватает ~85 000.
> Привычки под неё пока нет. Разбить на шаги и поставить первое — «разобрать подписки» — на четверг 18:00? Скажи «да».

## Что делаем

**Шаг 1. Чистое ядро `goal-intake.ts`** (без БД/ИИ): факты → максимум 3 строки + одно предложение.
- Деньги (сфера finance и есть сумма): «нужно ~X ₸/мес, свободно ~Y ₸/мес → влезает / не хватает Z». Если есть другие денежные цели — общий портфель («вместе с „машиной“ не хватает …»).
- Измеримая не-денежная (есть число): «это ~N в месяц (~M в неделю)».
- Время: цель на ~K ч/нед, неделя уже занята на P% → «впритык / влезает»; ближайшее окно — день и час.
- Привычки: есть подходящая непривязанная → «привязать «Бег»?»; нет → «привычки под неё пока нет».
- Финал — **одно** предложение действия с «да»: разбить на шаги + первое занятие в найденное окно.
- **Честность:** нет записанных доходов → про деньги ни одной цифры, а «доходов не записано — посчитать, хватит ли, не могу». Нет срока → «к концу года» (как уже считают коучи). Ни одной цифры не из БД.

**Шаг 2. Адаптер `gatherGoalIntake(userId, goalId)`**: собирает факты из готовых кусков выше. READ-ONLY, общий таймаут ~2,5 с, на любой сбой → `null` (цель всё равно записана, ответ как сегодня).

**Шаг 3. Чат:** `commitGoal` после записи дописывает разбор к «Цель записана…». Ответ сохраняется в историю (`saveTurn` уже так делает) → «да» идёт агенту с контекстом → он делает `decompose_goal` / `create_task` в окно / `create_habit` обычными инструментами под подтверждением. Новой машины состояний нет.

**Шаг 4. Экран:** `POST /goals/yearly` возвращает `intake: { text }` и кладёт тот же текст в чат сообщением робота (чтобы «да» голосом или текстом работало и после постановки с экрана). Мобилка: стор целей → `useRobotReactionStore` (эмоция `thinking`, облачко с разбором; облачко висит дольше обычных 9 с). OTA, без новой сборки.

**Шаг 5. Тесты, флаг, выкатка:**
- unit на ядро: деньги «влезает / не хватает / нет доходов», портфель, не-денежная, без срока, нет окна, нет привычек;
- интеграционные через настоящие пути `commitGoal` и `POST /goals/yearly`;
- тест мобильного стора;
- флаг `FEATURE_V2_GOAL_INTAKE`: выкл → ответ байт-в-байт как сегодня; по правилу «ship → flag=all» сразу `all`;
- push + `npm run ota`, живая проверка на телефоне: поставить тестовую цель → увидеть разбор → удалить её.

## Чего НЕ делаем (границы)

- Ничего не создаём без «да»: ни задач, ни привычек, ни лимитов.
- Только **годовые** цели (то, что сейчас «цель»). Месячные и недельные — потом, если понравится.
- Задачи не трогаем (там уже проверяются нагрузка дня и конфликт со встречей). Отдельные хвосты, НЕ в этом плане: с экрана не проверяется наложение задачи на встречу; задача не привязывается к цели.
- Не простыня: максимум 3 строки + вопрос. При спаде настроения (mood-tone) — без «не хватает», мягче: «посчитаем, как дотянуть, когда будешь готов».

## Риски

- **Лишний вызов ИИ** (оценка часов в неделю): только для не-денежных целей, 1 раз на постановку, есть фолбэк. Ок.
- **Медленный ответ:** таймаут 2,5 с → без разбора, как сегодня.
- **Неверные деньги, если доходы записаны не все:** формулировка «по записанным доходам и тратам за месяц», без категоричных выводов.
