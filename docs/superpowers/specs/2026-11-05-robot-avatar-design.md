# Робот-эпик, Часть 2: робот-аватар и эмоции с сервера

**Дата:** 2026-11-05 · **Статус:** решения Berik приняты (эмоции «сервер по фактам», робот как в прототипе) · **Эпик:** Часть 1 удалила питомца/Арену; Часть 3 — два экрана; Часть 4 — комната.
**Референс:** `~/Downloads/robot_companion.html` (прототип Berik, 2026-06-01), заметка памяти `robot_avatar_replaces_pet`.

## Цель
Один персонаж — робот-компаньон, «тело» единого мозга. Его эмоция на каждый ответ приходит с сервера (из фактов хода, без лишних вызовов ИИ), приложение только рисует.

## 1. Сервер: `emotion` в каждом ответе мозга

`type RobotEmotion = 'neutral' | 'happy' | 'love' | 'surprise' | 'worried' | 'confused' | 'caring' | 'thinking' | 'angry'`.

`JarvisResponse.emotion: RobotEmotion` — выставляется на КАЖДОМ пути `handleMessage` чистой функцией `emotionForTurn(facts)` (`src/services/robot-emotion.ts`, юнит-тестируемая):

| Факт хода (приоритет сверху вниз) | Эмоция |
|---|---|
| кризис (safety_crisis) | `caring` |
| сообщение эмоциональное (classifyEmotional / therapeutic-путь) | `caring` |
| ждёт подтверждения (pendingAction confirmable) | `thinking` |
| слот-вопрос «На что потратил?» | `confused` |
| инструмент/действие выполнено успешно (EXECUTABLE ok, «да» подтвердило, бронирование) | `happy` |
| отмена (cancel_pending) | `neutral` |
| сбой исполнения / «не получилось» | `worried` |
| стиль ассистента `toxic` (и не эмоциональный ход) | `angry` |
| в тексте юзера радость («ура», «получилось», «сделал!», «спасибо») | `happy` |
| иначе | `neutral` |

Проброс: `/voice/chat`, `/voice/process`, `/voice/conversation/{message,text}` добавляют `emotion` в ответ; `/voice/confirm-action` → `happy` (выполнено) / `neutral` (отмена) / `worried` (409 устарело). Старые клиенты поле игнорируют.

## 2. Мобилка: компонент `RobotAvatar`

`components/robot/robot-avatar.tsx` — собран из `View` (как CSS-прототип: капсула-голова 132×108 r32, экран 106×78 r18, тело 86×64, руки, антенна с жёлтой лампочкой), анимации — `react-native-reanimated` (уже в проекте; **новых нативных зависимостей нет**). Палитра прототипа: корпус `#E8E8F0`, экран `#23202F`, глаза `#6CF0FF`, тело `#6C63FF`, акцент `#FFD166`.

Пропсы: `emotion: RobotEmotion`, `size?: number` (масштаб), `attention?: 'idle' | 'listening' | 'reacting'`, `headTurn?: -1 | 0 | 1`.

Глаза (носитель эмоции; покой = чёрточки, эмоции «раскрывают»):
| Эмоция | Глаз (Ш×В, скругление, сдвиг) | Особое |
|---|---|---|
| neutral | 28×7, r5 | — |
| happy | 28×15, скругление только снизу 18, Y+5 | правая рука машет |
| love | 32×34 круг, цвет `#FF8FB1` | блик, пульс 1.08 |
| surprise | 34×36 круг | крупный блик |
| angry | 30×22 r7, цвет `#FF5247` | брови ±22° |
| worried | 28×20 r9 | дрожь, брови ∓17° |
| caring | 26×18 r11, Y+4, opacity .9 | мягкое веко |
| confused | левый 32×34, правый 18×20 круги | наклон −7° |
| thinking | 14×14 круг, сдвиг (−6,−4) | наклон −7° |

Всегда: дыхание (−6px, 3.6с), пульс антенны (1.8с), моргание раз в 3–6с (глаз → 3px), переходы 280мс с пружиной. Цикл внимания: `listening` (юзер пишет/говорит) — уменьшается до 0.74 и чуть косится; `reacting` — вырастает, держит эмоцию ~2.5с, затем `idle` с `neutral`.

Модуль `services/robot-emotion.ts` (чистый, jest): `eyeShapeFor(emotion)` → параметры глаз; `normalizeEmotion(unknown)` → валидная эмоция или `neutral`.

## 3. Где робот появляется в Части 2
Пока экраны не переделаны (это Часть 3): робот — в шапке Чата (реагирует на ответ: эмоция из `/voice/chat`, `listening` пока юзер печатает/говорит) и на Дашборде вместо удалённого питомца (реагирует на голосовые команды из `use-voice`: эмоция из `/voice/process`/`confirm-action`). Часть 3 перенесёт его в двухэкранную схему.

## Тесты
- Сервер unit: `emotionForTurn` — таблица выше (каждая строка + приоритеты: кризис > эмоц. > pending > …).
- Сервер it: `/voice/process` и `/voice/chat` отдают `emotion` (расход → `thinking`; задача → `happy`; кризис → `caring`; отмена → `neutral`).
- Мобилка jest: `normalizeEmotion`, `eyeShapeFor` (все 9), chat-store сохраняет `emotion`, use-voice-путь отдаёт эмоцию.
