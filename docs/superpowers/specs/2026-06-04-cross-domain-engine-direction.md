# Кросс-доменный движок взаимосвязей — НАПРАВЛЕНИЕ (north-star slice)

> Зафиксировано 2026-06-04. Это **scope/направление**, НЕ готовый план.
> Перед кодом — полный цикл: brainstorm → спека → writing-plans → TDD.
> Цель: превратить «взаимосвязь доменов» из побочки в считающий движок —
> главное сообщение продукта, «чего нет ни у кого вместе».

## Проблема (по факту кода, 2026-06-04)
Кросс-доменное рассуждение сегодня = «**собрать факты каждого домена по
отдельности → свалить в системный промпт → надеяться, что LLM свяжет**».
- Домены гребутся силосами: `gatherDayLoad/WeekLoad/MonthLoad`,
  `gatherAssistantContext`, `fetchV2EnrichmentData` → склейка в текст →
  `buildV2EnrichmentBlock` в `jarvis-orchestrator.ts:1004`.
- Связи **эмерджентные** (LLM импровизирует каждый ход), значит:
  1. **недетерминированно** — связал сейчас, забыл потом;
  2. **неполно/окнами** — связывает только то, что попало в промпт хода;
  3. **часть — заглушки**: реально считается пейсинг **только денежной** цели
     (`goal-pace.ts`/`computeSavingsPace`, гейт `isMoneyGoal`); «поведение→цель»,
     «перерасход↔настроение», «обязательства↔цель» НЕ вычисляются;
  4. **нет запрашиваемой структуры** — есть граф ЛЮДЕЙ (Entity↔Entity), нет
     графа ДОМЕНОВ; «карта взаимосвязей» = документ, не рантайм-данные.

## Что значит «оживить» (3 столпа)
1. **Считать настоящие кросс-доменные числа** (не заглушки/молчание):
   - пейсинг для ВСЕХ измеримых целей (не только денег);
   - импакт трат/привычек/обязательств на цель («доставка ест цель на X%»);
   - корреляции: настроение↔выполнение, перерасход↔просадка, сон↔продуктивность.
2. **Смоделировать связи как ДАННЫЕ** — слой взаимосвязей: рёбра
   `{ sourceDomain, targetDomain, relation, weight, computedImpact, validAt }`,
   которые можно СТРОИТЬ и ЗАПРАШИВАТЬ («покажи всё, что влияет на цель X»).
   Паттерн — как entity-graph, но между доменами (деньги/цель/привычка/
   настроение/обязательство/календарь).
3. **Рефлектор считает инсайты заранее и хранит их** → мозг ВЫДАЁТ детерминированно,
   а не импровизирует. enrichment передаёт **вычисленные инсайты**, не сырые факты.

## Что переиспользуем (не с нуля)
- `goal-pace.ts` / `savings-pace.ts` — расчёт пейсинга (расширить с money-only).
- `reflector-v2/gather-facts.ts` (кросс-тир чтение) + `synthesize.ts` — основа
  для «считать+хранить инсайты».
- `v2-enrichment` — точка, куда вливать вычисленные инсайты.
- Движок пересечения (day/week/month/year load) — уже считает нагрузку; рёбра
  «план↔календарь↔задачи» частично есть.
- Граф людей — как образец «связей как данных».

## Дыры из interconnection_map (память) — закрыть
- `goalsBehind:0` захардкожен → считать реально.
- Нет числового таргета у немонетарных целей → ввести target для измеримых.
- Нет live «кто/что влияет сейчас» → запрашиваемый граф.

## Декомпозиция (черновик — уточнить в brainstorm)
- **Срез 1:** один считающий мост, который УЖЕ ценен и доказуем — напр.
  «траты/обязательства → пейсинг денежной цели» с реальным числом + проактивный
  вывод. (Минимум нового, максимум вау, переиспользует goal-pace + obligations.)
- **Срез 2:** слой взаимосвязей как данные (рёбра домен→домен) + запрос.
- **Срез 3:** рефлектор считает+хранит набор инсайтов; enrichment отдаёт их.
- **Срез 4:** немонетарные измеримые цели + корреляции настроение/сон/выполнение.

## Дисциплина
Каждый срез — полный цикл (brainstorm→спека→план→TDD→ревью→деплой), флаг-гейт,
money-safety, off=байт-идентично. Сервер-only (мозг живёт на бэке — это важно для
обновлений: см. ниже).

## ВАЖНО для обновлений у тест-юзеров
Этот движок — **СЕРВЕРНЫЙ** (packages/server, Railway). Значит улучшения
доезжают до ВСЕХ мгновенно по `git push` → Railway deploy, **без обновления
приложения/APK** (мобайл — тонкий клиент к серверу+боту). APK пересобирать не
нужно для изменений мозга.
