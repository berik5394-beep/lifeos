# Экран календаря (мобайл) — Design

> Brainstormed + одобрено Berik 2026-06-04. Mobile-only (`apps/mobile`,
> React Native + Expo). Для первой TestFlight/веб-PWA сборки друзьям.
> Веб-безопасно (ноль новых нативных зависимостей).

## Проблема / ценность
У задач/привычек/целей/финансов есть экраны, у **календаря — нет**, хотя на
бэке `CalendarEvent` + `/events` живут. Нужен экран-витрина: месячная сетка,
где видно как прошёл/идёт месяц — дни закрашены по % выполнения, видны
галочки/перечёркивания планов и события; тап по дню → детали дня.

## Решения брейншторма (зафиксировано)
1. **Навигация:** отдельный push-экран, открывается **с дашборда** (кнопка
   «Календарь»). Табы НЕ трогаем (их 6: Дашборд/Задачи/Привычки/Цели/Финансы/Чат).
2. **Тап по дню:** нижняя панель с деталями дня, **read-only** (редактирование
   уже есть на экране Задачи; из панели — ссылка «Открыть в Задачах»).
3. **Робот:** в v1 НЕ включаем (аватара-робота в приложении ещё нет; добавится
   с 2-экранным робот-UX позже).
4. **% дня:** = задачи (выполнено/всего за дату), ровно как существующий heatmap
   на дашборде. Привычки — fast-follow (их логи за месяц тянутся отдельно).

## Что переиспользуем (НЕ с нуля)
- Цветовая шкала % из `components/charts/heatmap.tsx` (`getColor`: серый →
  `#064E3B` → `#059669` → `#34D399` → `#22C55E`). Вынести в общий хелпер, чтобы
  heatmap и календарь делили одну шкалу (без дублирования).
- `stores/task-store.ts` — задачи за период (per-day done/total).
- `stores/event-store.ts` — `fetchEvents({month})`, события с датой/временем.
- `utils/dates.ts` (`formatDate`, `isToday`, и т.п.), русские месяцы/дни
  (уже как константы в `tasks.tsx`), UI-кит (`Card`, `Modal`), `Feather`-иконки,
  `useColors`, `api`-клиент. Календарная математика месяца — по образцу
  `buildGrid` из heatmap.

## Подход (выбран A)
Свой лёгкий компонент `MonthCalendar` на `View/Pressable`. Отвергнуты: B
(`react-native-calendars` — новая зависимость с веб-проблемами, ломает PWA),
C (расширять heatmap — мусорит чистый год-компонент).

## Архитектура / файлы
| Файл | Ответственность |
|---|---|
| `app/calendar.tsx` | Экран: шапка (‹ Месяц Год ›) + `MonthGrid` + `DayDetailSheet`. Тянет задачи+события за месяц, считает per-day % и множество дней-с-событиями, держит выбранный день. |
| `components/calendar/month-grid.tsx` | **Чистый presentational** компонент сетки 7×6. Props: `year`, `month`, `dayStats: Record<'YYYY-MM-DD', DayStat>`, `onDayPress(dateKey)`. Рендерит ячейки: фон по %, число, маркеры (✓/✗/точка), обводка «сегодня», приглушение чужого месяца. |
| `components/calendar/day-detail-sheet.tsx` | Нижняя панель (`Modal`): дата, задачи дня (✓/✗ read-only), события дня, кнопка «Открыть в Задачах». Props: `dateKey`, `tasks`, `events`, `onClose`, `onOpenTasks`. |
| `components/calendar/calendar-logic.ts` | **Чистые хелперы (юнит-тест):** `buildMonthMatrix(year,month)` → недели/дни; `computeDayStats(tasks)` → `Record<date,{donePct,total,done,hasOverdue}>`; `dayMarker(stat, hasEvent, isPast)` → `'check'|'cross'|'dot'|'none'`; цветовая шкала. |
| (modify) `app/(tabs)/index.tsx` | Кнопка/иконка «Календарь» → `router.push('/calendar')`. |
| (возможно) `components/charts/heatmap.tsx` | Импортировать общую цветовую шкалу из `calendar-logic` вместо локального `getColor` (DRY, без изменения вида). |

## Типы (ядро)
```ts
interface DayStat {
  total: number;      // задач на этот день
  done: number;       // выполнено
  donePct: number;    // 0..100 = round(done/total*100), 0 если total=0
  hasOverdue: boolean;// есть невыполненная задача в прошлом дне
}
type DayMarker = 'check' | 'cross' | 'dot' | 'none';
```

## Поток данных
1. Экран при маунте/смене месяца: `task-store.fetchTasks` (за месяц) +
   `event-store.fetchEvents({ month })`.
2. `computeDayStats(tasks)` (клиент) → `Record<date, DayStat>` (как дашборд).
3. Множество дат-с-событиями из `events`.
4. `MonthGrid` рисует: фон ячейки = шкала(`donePct`); маркер =
   `dayMarker(stat, hasEvent, isPast)`:
   - `check` — `donePct===100 && total>0`;
   - `cross` — `total>0 && hasOverdue` (были планы, часть просрочена/не закрыта в прошлом);
   - `dot` — есть событие, но не check/cross;
   - `none` — пусто.
5. Тап по дню → `DayDetailSheet` с задачами этого дня (✓ done / ✗ невыполненные)
   + события (время+название). «Открыть в Задачах» → переход на экран Задачи на
   эту дату.

## Маркеры (визуально)
- ✓ зелёная галочка — день закрыт на 100%.
- ✗ перечёркнуто — были задачи, часть не закрыта (для прошлых дней — «провалено»).
- • точка — на день есть событие/встреча.
- Приоритет одного значка на ячейку: check > cross > dot (фон % несёт остальное).

## Ошибки / край
- Offline → показываем что есть в сторе (offline-first уже в `api`-клиенте).
- Пустой месяц → серая сетка, панель дня: «На этот день ничего не запланировано».
- Загрузка → спиннер в шапке (не блокирует сетку).
- Будущие дни с задачами без выполнения — НЕ `cross` (не провал, ещё не наступил):
  `hasOverdue` считается только для прошлых/сегодня.

## Тестирование
- **Юнит (как везде в проекте):** `calendar-logic.ts` — `buildMonthMatrix`
  (число дней, выравнивание на Пн, дни соседних месяцев), `computeDayStats`
  (done/total/pct, пустой день, hasOverdue только для прошлого), `dayMarker`
  (приоритет check>cross>dot, будущее не cross).
- RN-рендер юнитом НЕ покрываем (нет смысла) — Berik проверяет визуально на
  сборке и говорит что докрутить.

## Не-цели (v1)
Редактирование из календаря, привычки в %, робот-комментарий, неделя/год-режимы,
drag-перенос, синк-индикаторы Google. Всё — потом.

## Rollout
Mobile-only, серверных изменений ноль. Коммит на шаг. Попадает в первую
веб-PWA / TestFlight сборку. Berik смотрит экран вживую → итерация по виду.
