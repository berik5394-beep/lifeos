# Phase 6 — Therapeutic Friend Layer

**Промт для агента-исполнителя.** Скармливать одним сообщением, без сокращений. После Phase 5 (планировщик + базовый рефлектор) полностью закрыта.

---

## Контекст

Прочти `docs/migration/VISION-WISE-FRIEND.md` целиком до начала. Это видение продукта, без которого этот промт не имеет смысла.

## Задача

Phase 6 — построить **Therapeutic Friend Layer** поверх Phase 5. Это не новый продукт и не замена существующего функционала. Это **четыре дополнительных слоя**, которые превращают LifeOS из «AI с памятью и планами» в «AI-наставника, который знает тебя и помогает прожить жизнь лучше».

Существующий функционал (задачи, привычки, календарь, финансы, travel, реактивные ответы, planner, basic reflector) **остаётся как есть**. Phase 6 не трогает их код — только добавляет слои поверх.

## Видение в одной фразе

LifeOS становится единственным продуктом на пересечении трёх рынков (AI-терапия + Productivity + AI-ассистенты), которым **нет аналога**. Технологически: глубокая интеграция данных жизни + долгая память + проактивная мудрость + терапевтическая тактичность.

## Что считается провалом задачи

Я отклоняю результат, если:

1. **Позиционирование «психолог» или «терапевт» попало в код, промпты, UI или App Store description.** Должно быть исключительно «мудрый друг», «наставник», «личный советник». Юридическая необходимость, не косметика. Любое появление слова «терапевт»/«психолог» в user-facing тексте — PR отклонён.

2. **Safety layer не построен или построен после терапевтического функционала.** Распознавание кризиса + ресурсы помощи + дисклеймер должны быть **первым** коммитом Phase 6, не последним. Без них терапевтические промпты в проде — это юридический и этический риск.

3. **`UserProfile` синтезируется агентом при каждом запросе вместо периодической рефлексии.** Это сжигает деньги и не даёт стабильности. Профиль обновляется **раз в неделю** (или при крупных событиях), хранится в Postgres, читается из БД во время диалога.

4. **Терапевтический режим включён по умолчанию для всех запросов.** Он активируется **только** для эмоциональных тем, определённых классификатором. Запрос «запиши расход 5000» не должен получать ответ «как ты себя чувствуешь по этому поводу?».

5. **Trigger detection превратился в спам.** Жёсткое правило: **не более одной проактивной therapeutic-инициативы в день**. Если пользователь dismiss'нул insight по теме — молчим про эту тему минимум 7 дней.

6. **Кризисные диалоги используются для обучения / анализа / метрик.** Sensitive conversations имеют отдельный flag `crisis: true`, исключаются из analytics, шифруются at-rest, retention 30 дней максимум.

7. **Phase 6 начат до того, как Phase 5 закрыта полностью** (планировщик работает end-to-end, decompose_goal делает реальное дерево, рефлектор пишет insights, тесты зелёные, 24 часа стабильности в проде).

## Что считается успехом

Четыре новых компонента, каждый — отдельный коммит, в порядке снизу вверх (safety первым).

### Компонент 1: Safety Layer (первый коммит)

`services/safety-classifier.ts`:
- Распознаёт кризисные сигналы (готовый список фраз + Claude Haiku-классификатор)
- Триггер-фразы: упоминания суицида, самоповреждения, насилия, острого отчаяния
- При срабатывании → response не от LifeOS-промпта, а из захардкоженного safety-template'а
- Возвращает: эмпатичное короткое сообщение + ресурсы профессиональной помощи + предложение «хочешь, я помогу найти специалиста?»

`data/crisis-resources.ts`:
- Список ресурсов для Казахстана (горячие линии, центры помощи)
- На русском и казахском
- Обновляется при необходимости, в коде статично

`prisma schema`:
- Поле `crisis: Boolean @default(false)` на `ChatMessage`
- Sensitive messages помечаются при сохранении
- Отдельный retention: 30 дней максимум

Дисклеймер в onboarding и settings:
- *«LifeOS — твой AI-друг, но не замена профессиональной помощи. Если ты в кризисе — обратись к специалисту: [ресурсы]»*
- Видим в onboarding, всегда доступен в settings

### Компонент 2: UserProfile (второй коммит)

Новая таблица `UserProfile` в Postgres:
```prisma
model UserProfile {
  id          String   @id @default(cuid())
  userId      String   @unique
  user        User     @relation(fields: [userId], references: [id])
  values      Json     @default("[]")        // ["family-oriented", "career-driven", ...]
  triggers    Json     @default("[]")        // ["criticism", "money pressure"]
  patterns    Json     @default("[]")        // ["abandons habits week 3"]
  styleNotes  String?                        // "direct, no fluff, ценит конкретику"
  relationships Json   @default("{}")        // {"мама": "сложно, но люблю", "Серик": "бизнес"}
  lastSynthesizedAt DateTime?
  synthesisVersion  Int @default(0)          // для будущих миграций структуры
  updatedAt   DateTime @updatedAt
}
```

`services/profile-synthesizer.ts`:
- Запускается раз в неделю по cron (воскресенье вечером) или при крупном событии (новая цель, кризис)
- Читает: последние 100-300 ChatMessage + все Memory с importance ≥ 5 + завершённые задачи/привычки + Insights рефлектора
- Через Claude Sonnet (не Haiku — нужна глубина) синтезирует профиль
- Пишет в `UserProfile`, инкрементит `synthesisVersion` при структурных изменениях

`runRegistryTool` для оркестратора:
- При формировании контекста для ответа подмешивает релевантные части профиля
- Не весь профиль (это болтливо), а **то что релевантно текущему запросу**
- Tool `get_user_profile` доступен агенту и оркестратору как любой другой

### Компонент 3: Therapeutic Prompting Mode (третий коммит)

`services/emotional-classifier.ts`:
- Определяет, является ли сообщение эмоциональным (а не транзакционным)
- Эмоциональное: про чувства, отношения, кризисы, ценности, сомнения, переживания
- Не эмоциональное: «запиши расход», «когда у меня встреча», «какая погода»
- Через Claude Haiku, fast + cheap

`prompts/therapeutic-mode.ts`:
- Отдельный system prompt для эмоциональных диалогов
- Жёстко зашитые паттерны:
  - **Отражение чувств**: *«Звучит, что было тяжело»*
  - **Открытые вопросы**: *«Что для тебя сейчас важнее?»*
  - **Валидация**: *«Понимаю, почему ты так среагировал»*
  - **Conditional advice**: *«Если хочешь — поделюсь мыслью. Не хочешь — просто слушаю»*
  - **Memory recall с заботой**: *«Помнишь, две недели назад ты говорил Y? Сейчас похоже на повторение?»*
- Запрет на: указания (*«ты должен»*), диагнозы, медицинские советы, прямые рекомендации без приглашения
- Приоритет: слушать > спрашивать > предлагать > советовать

Интеграция в оркестратор:
- При входящем сообщении: `emotional-classifier` определяет режим
- Если эмоциональный — `therapeutic-mode` prompt + UserProfile контекст
- Если транзакционный — обычный режим (как сейчас)
- Гибрид (например «запиши, что поссорился с Сериком на 5000» — finance + emotion): сначала транзакция, потом мягкое отражение

### Компонент 4: Trigger Detection в Reflector (четвёртый коммит)

Расширение `reflector-service.ts` (из Phase 5) с эмоциональными триггерами:

`detectors/burnout-detector.ts`:
- 5+ встреч в день несколько дней подряд → предложить отдых
- 7 дней подряд переработка по календарю → «хочешь спланировать выходной?»

`detectors/sleep-disruption-detector.ts`:
- Резкое падение сна в дневнике (более 30% от обычного) → «как ты?»
- Не каждый день, не «доброе утро как спалось» — а только при реальном disruption

`detectors/conflict-followup-detector.ts`:
- Упоминание ссоры/конфликта в чате
- Через 24-48 часов: *«Я заметил, ты упоминал X. Как ты сейчас?»*
- Только один follow-up, не серия

`detectors/missed-important-date-detector.ts`:
- Memory с типом `important_date` + дата сегодня
- *«Сегодня день рождения мамы — поздравил?»*
- Деликатно, не настойчиво

`detectors/intention-deviation-detector.ts` (из Phase 5 intentions):
- Зафиксированное намерение vs наблюдаемое поведение
- *«Ты говорил, что хочешь меньше тратить на еду. Эта неделя — на 30% больше прошлой. Хочешь обсудить?»*

Все детекторы выдают `Insight` с `severity` и `kind: 'therapeutic'`.

Rate-limit:
- **Не более 1 therapeutic-инициативы в день** (отдельно от обычных insights рефлектора)
- Если dismissed — молчим про тему 7 дней минимум
- Если 3 раза подряд dismissed по типу триггера — снижаем чувствительность этого триггера для этого юзера

## Где ты упрёшься и что я приму в ответ

**Возражение «эмоциональный классификатор будет ошибаться, начнёт включать терапевтический режим для безобидных запросов»**. Принимаю. Решение: **conservative bias** — при неуверенности классификатор возвращает «транзакционный». Лучше пропустить эмоциональный момент, чем напугать пользователя «как ты себя чувствуешь?» в ответ на «запиши расход». Тесты: 30 фраз с ожидаемой классификацией, 80% точность минимум.

**Возражение «UserProfile через Claude Sonnet раз в неделю на 1000 пользователей — это дорого»**. Реальное. Решение: синтез только для **активных** пользователей (≥10 взаимодействий за неделю). Для остальных — пропускаем. Также: только при наличии **новых данных** (lastSynthesizedAt < последняя активность). Cost оценочно: 1000 активных × $0.05 за рефлексию = $50/неделя = $200/месяц. Приемлемо.

**Возражение «trigger detection превратится в "AI лезет в душу", пользователи будут раздражаться»**. Самый реальный риск Phase 6. Решение многослойное: (а) жёсткий rate-limit (1/день), (б) dismiss-learning (3 dismiss → молчим про тип), (в) тон проактивных сообщений всегда **наблюдение, не диагноз** — «я заметил X» не «ты в выгорании», (г) пользователь может полностью отключить therapeutic mode в settings — он становится обычным productivity-AI. Опция должна быть явной.

**Возражение «safety-классификатор может пропустить кризис или ложно сработать»**. Серьёзное. Решение: **bias к ложным срабатываниям**. Лучше показать ресурсы помощи человеку который не в кризисе, чем пропустить настоящий. Список триггер-фраз — широкий. Дополнительно: пометка `crisis: true` ставится **постоянно** (нельзя «отменить») для будущего аудита. Никакой ML без human-review для кризисных кейсов.

## Фиксированный порядок работ

0. Подтверди, что Phase 5 закрыта полностью (планировщик строит деревья в проде, рефлектор пишет insights, тесты зелёные, 24+ часа стабильно).
1. **Safety Layer первым.** Без этого Phase 6 не катить даже в staging. Schema (`crisis: Boolean`), `safety-classifier`, `crisis-resources`, дисклеймеры в onboarding/settings, тест на 10 кризисных фраз + 10 безопасных.
2. **UserProfile + synthesizer.** Schema, weekly cron, tool `get_user_profile`, интеграция в context-builder оркестратора. Тест: для тестового пользователя с заданной историей синтезируется ожидаемый профиль.
3. **Emotional classifier + therapeutic prompting mode.** Classifier-сервис, отдельный system prompt, интеграция в оркестратор. Тест: 30 фраз классификация (precision/recall ≥ 80%), 10 эмоциональных диалогов с проверкой паттернов (отражение, открытые вопросы, valid).
4. **Therapeutic trigger detectors в Reflector.** 5 детекторов как отдельные модули, каждый с тестом на synthetic snapshot. Интеграция в рефлектор с rate-limit (1/день) и dismiss-learning.
5. **Settings: opt-out для therapeutic mode.** Тумблер «общаться как друг (с эмоциональной поддержкой)» / «отвечать только по делу». UI + backend respect.
6. **End-to-end smoke в проде**: 10 сценариев (5 эмоциональных, 5 транзакционных, 2 кризисных), все ведут себя как описано в спеке.

## Тесты-инварианты, обязательные в PR

1. `safety-recall.test.ts`: 10 фраз с кризисными сигналами → классификатор срабатывает в 100% случаев. False negatives = 0.
2. `safety-precision.test.ts`: 20 безопасных фраз с потенциально триггерными словами («умираю от смеха») → не срабатывает.
3. `emotional-classifier.test.ts`: 30 фраз → ожидаемая классификация, precision ≥ 80%.
4. `therapeutic-mode-patterns.test.ts`: 10 эмоциональных диалогов → ответы содержат хотя бы один из терапевтических паттернов (отражение/открытый вопрос/валидация).
5. `therapeutic-rate-limit.test.ts`: 5 триггеров за день → отправлен максимум 1 therapeutic insight, остальные в feed.
6. `profile-synthesis.test.ts`: для тестового пользователя с заданной историей синтез выдаёт профиль с ожидаемыми traits.
7. `crisis-message-isolation.test.ts`: message с `crisis: true` не попадает в analytics-export, не используется для profile-synthesis.
8. `therapeutic-opt-out.test.ts`: пользователь с `therapeuticMode: false` получает только транзакционные ответы, даже на эмоциональные фразы.

## Что я не приму

- «Сделаем safety после, сначала весь функционал» — нет. Safety первым коммитом. Без исключений.
- «Therapeutic mode по умолчанию для всех» — нет. Активируется классификатором, opt-out в settings.
- «UserProfile синтезируем при каждом запросе» — нет. Раз в неделю, в БД.
- «Trigger detection раз в час» — нет. Rate-limit 1/день, dismiss-learning обязательно.
- «Кризисные диалоги используем для аналитики» — нет. Изолированы, шифруются, retention 30 дней.
- «Позиционирование "AI-психолог" — это привлечёт пользователей» — нет, это нарушит закон и принципы. «Мудрый друг», точка.

## Дополнительный контекст «зачем это нужно»

Без Therapeutic Friend Layer LifeOS — хорошо построенный, но **обычный AI-ассистент**. У OpenAI и Anthropic есть всё, чтобы построить такое через 6 месяцев — и у них дистрибуция, которую ты не победишь.

С этим слоем LifeOS становится **категорией, которой нет**. Не «ChatGPT который ещё и задачи помнит», а **«единственный AI, который знает мою жизнь и помогает её прожить»**. Это эмоциональный моат, который не повторишь промптом — нужны годы накопленной памяти + аккуратно построенная архитектура + доверие пользователя.

Если получится — у тебя есть продукт, ради которого люди готовы платить $20/месяц, потому что цена пропустить терапевта или потратить вечер на планирование выше.
